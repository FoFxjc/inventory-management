System Reference

Factory Inventory Management — Architecture

A three-tier demo application: a Vue 3 single-page app talks to a FastAPI backend over JSON, which filters an in-memory copy of the data on every request. Nothing is persisted — the JSON files under server/data/ are the only source of truth, reloaded fresh each time the server starts.

Vue 3 · Composition API Vue Router 4 Axios Vite 5 FastAPI Pydantic v2 Uvicorn No database

Request / Data Flow

01

A user changes a filter in FilterBar.vue (Time Period, Warehouse, Category, or Order Status) — the shared state lives in the useFilters composable, not the component.

02

The active view (e.g. Dashboard.vue) reads the current filters and calls its loader, which sets loading.value = true and awaits api.js.

03

api.js builds a query string, skipping any filter set to "all", and sends the request with axios — e.g. GET /api/dashboard/summary?warehouse=West&month=2025-09.

04

FastAPI routes the request to a handler in main.py, which runs apply_filters() / filter_by_month() over the in-memory list already loaded by mock_data.py.

05

The filtered result is validated against a Pydantic response_model and returned as JSON — malformed data raises a 422 before it reaches the client.

06

Back in the view, the response is stored in a raw ref (e.g. allOrders); computed properties derive totals, chart series, and table rows, and Vue re-renders the affected DOM only.

Worth Knowing

api.js calls two endpoints main.py doesn't define. The client's getTasks, createTask, toggleTask, deleteTask, createPurchaseOrder, and getPurchaseOrderByBacklogItem target /api/tasks and /api/purchase-orders, but no matching routes exist in server/main.py today — those calls will 404 until the routes are added.
